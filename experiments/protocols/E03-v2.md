# E03 v2：记忆表示、注入容量与记录一致性

版本：e03-v2-20261022。状态：工程比较协议与执行器；尚无新模型效果结果，不是已注册的确认性研究。旧 E03/E03c 原始文件、原协议与假设状态保留。本文规定新版本的方法，不追溯改写 2026-09 的运行。

## 1. 问题与当前范围

在明确的任务、读取者与容量范围内，记忆表示、注入容量及二者的交互怎样影响表现？本轮执行器只处理这个问题。跨读取者的 E03c 属于另一项设计，需要各读取者自己的无记忆基线，不能用本轮替代。

旧拆分 A 的汇总/检查点记为 72/80，保存轨迹记为 70/80，差异涉及 sortkey-03 的 r2、r3。有效分析记录集尚未裁定。旧基线、所有依赖它的相对效应与效率继续暂停；三个记忆臂间可追溯的直接比较仍保留。新运行使用新目录、新配置与新轨迹，不与旧成绩拼接，也不据此宣布旧冲突已解决。

## 2. 七个比较臂

| 记忆表示 | 低注入容量 | 高注入容量 |
| --- | --- | --- |
| 原始来源截取 raw | raw-cL | raw-cH |
| 自然语言摘要 summary | summary-cL | summary-cH |
| 结构化观察与边界 structured | structured-cL | structured-cH |

另设同期无记忆基线 baseline。L、H 是运行前固定的两个不同正整数，写入 plan.json；示例数字只用于装置预检，不代表最优值或已批准的正式设计。

“形式”在这里指明确的表示生成流程。摘要可能丢失信息，结构化生成可能改变内容，截断可能移除字段。比较结果不能全部归因于字段名或排版。容量操作是注入上限，应报告每臂实际长度、是否截断、完整文本与展示文本的身份；如果实际长度未随上限改变，应如实说明操纵没有改变该条输入。

## 3. 同源与检索

先用无记忆的固定协议执行器完成预先列明的来源任务，记录实际可写源码的最终内容、执行动作、验收判定及原轨迹哈希。受保护测试内容不进入经验渲染载荷。

每份来源只调用一次摘要生成和一次结构化生成，所有容量共用相应的完整文本。渲染器不被强迫为成功轨迹编造模型缺陷；结构化字段为 observation、applies_when、unverified。字段检查只说明格式符合要求，不认证内容真值。渲染失败或格式失配保留记录并停止，不能反复生成后挑选有利文本。

检索只根据评价任务公开陈述与来源任务陈述的 Unicode 二元组交集排序，同分按来源任务 ID 排序。检索不读取验收结果、族标签或各表示的文本。每道评价题的来源 ID 集合先确定，再用于全部表示和容量，避免检索变化被当成表示收益。

## 4. 容量计量

真实模型工程运行要求本地 tokenizer.json、文件哈希与可用的 tokenizers 运行库；不自动安装或下载。禁用特殊 token 后按该冻结分词器的完整计数约束经验块。这个单位是声明的参考分词器 token，并非服务商计费 token；参考分词器是否与读取者一致必须另行确认。公共提示头不计入经验容量，但在所有记忆臂相同，并进入完整请求和服务端用量记录。

同一完整经验块采用预先规定的字符前缀截断规则，逐次精确计数至不超过上限，不使用字符数除以四估计容量。原始片段过长或结构化字段被截断的情况保留记录。生成成本与实际注入量分别报告。

离线夹具使用明确标为 fixture_characters_NOT_model_tokens 的字符计数器，只检查流程。真实模型模式拒绝此计数器。离线夹具的模拟用量同样不能充当真实计费 token。

## 5. 任务与运行顺序

来源任务和评价任务 ID 全局唯一，族集合互不重叠；每个任务的陈述、文件、受保护文件、验收命令与拆分身份完整写入冻结计划。沿用公开或已经分析过的任务，只能产生相应范围的工程/探索观察；不能重新称为未见的确认集。

对同一评价题执行全部七臂及相同次数的重复。顺序由固定计划种子生成并写成完整调度表，运行时不按成绩改序。种子约束本地调度；旧后端没有向服务商传递随机种子，因此不得声称服务端采样被逐次配对或确定重现。

执行器使用固定 ProtocolAgentV3 循环，允许公开文件读取、可写源码修改和任务内验收；这一循环与旧 E03 不完全相同，新结果另行解释。所有臂的调用、步骤及验收条件相同。受保护文件在执行前后核对身份，验收超时或文件身份损坏标为未得到有效判定并中止，不默认为任务失败。

本地文件权限与校验不等于操作系统隔离。真实生成代码的执行环境需要与研究使用场景匹配；本次离线验收只执行自带的小型确定性夹具。

## 6. 证据、成本与续跑

每次调用在发送前保存 request.json，响应或错误另写 receipt.json。请求绑定计划哈希、阶段、单元、模型配置与原始消息；响应保存原文、服务端模型身份和原始用量。后端重试设为零，避免未记账的隐藏重试。缺少服务端用量或返回模型身份不符时保留原记录并中止。

来源、渲染、评价各自的单元记录把输入身份、调用回执、轨迹、判定及产物哈希连接起来。已经提交的单元文件不覆盖。汇总与检查点只是从这些记录生成的缓存：恢复时重新核对所有已完成单元和各阶段成本，不能从空副账开始累加。

在完整单元之间的受控暂停可续跑。如果在一次发送、响应、验收或提交中途失效，留下未决调用或未封存单元，自动续跑会拒绝，避免重新付费、替换结果或漏掉成本。未知消耗明确为未知。需要调查后另立新运行；不得删除不利或未决单元后把余下部分当作完整结果。

整个运行的发送预约数上限从来源数、渲染数、评价单元数和每回合调用上限推导。token 用量和墙钟检查包含返回后的停止检查；不宣称这构成服务商美元硬上限，也不宣称能撤销已经发送的请求。美元费用保持未知，直到有可追溯计价依据。

## 7. 分析

先确认七臂 × 全部题 × 全部重复完整，并逐项验证轨迹、判定、用量、计划及汇总相符，再做分析；缺失不能补零。

预先列明的主比较是：高容量下 structured−summary 的差，减去低容量下的同一差，即表示与容量的交互。其余固定容量的表示差、固定表示的容量差及相对基线差作为描述性辅助比较。

同一题的重复先求题均值，再求族均值，最后对本次各族等权汇总。描述性区间按族整体重采样，保持同题各臂与重复结构。少量、定向挑选的族不能代表任意新族；只有一个族时不输出族重采样区间。区间跨零不证明等价，辅助区间不自动成为经过多重比较控制的判决。

旧 330/267 题的历史精度估算不移作本轮功效依据。未来确认性研究需要另外固定目标效应、任务族抽样、相关结构、错误控制与样本规划。当前工程运行不自动改变历史 P3/P3b 的 open 状态。

## 8. 离线验收与入口

> **公开版读者说明。** 下文的 revised-source 指完整维护档案的源码根目录，包含以下三条命令所需的 E03 v2 执行器与测试。公开预览收录了旧 E03 的两份判定来源。要核对拆分 A 的基线冲突，请在仓库根目录运行 `python calculations/compare_e03_baseline.py`。输入与计数口径见[公开材料与复算](../../analysis/README.md)。

从本目录所属 revised-source 根目录运行：

```text
python -B -m unittest experiments.lab.test_e03_v2 -v
python -B -m experiments.lab.run_e03_v2 fixture --out <新的离线产物目录>
python -B -m experiments.lab.run_e03_v2 verify --run <离线产物目录>/run
```

freeze 子命令接受明确列出的来源和评价任务目录，产生不可覆盖的 plan.json，不发送模型请求。run 子命令读取计划；真实模型需要显式选择对应执行模式，使用本地已有凭据。该执行参数仅用于避免误触发，不能代替用户授权。

对已完整提交单元的暂停，可使用同一计划、同一运行目录加 --resume 继续。analyze 只读取完整且核验一致的运行，另存新分析文件。

## 9. 本轮不作的科学宣告

离线装置通过不表示记忆有效、某种形式更好、E03 历史来源冲突已裁定、费用已知或研究假设获得支持。它提供的是可执行的比较设计、记录规则和已测试的软件行为。旧书稿和已交付结果仍按原身份保留。
